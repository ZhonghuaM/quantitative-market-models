# Experiment guide

## The question

Do simple daily price-and-volume features improve next-observation direction forecasts over simple baseline forecasts? Separately, how sensitive is a probability-threshold trading illustration to execution timing and costs? Predictive discrimination, probability quality, and trading returns answer different questions.

This is an exploratory experiment on an already inspected historical sample. There is no untouched final holdout, and the defaults are not independently validated choices.

## Run and inspect

Follow the [installation commands](../README.md#run-the-study), then run `python scripts/run_analysis.py` from the repository root. The default `--study signal` regenerates the primary study's tables, figures, summary, and run manifest. Use `--study all` to include the separate portfolio, risk, derivatives, time-series, retrieval, and numerical examples. Supplementary outputs left in `reports/` are not necessarily regenerated by a signal-only run; use its manifest to identify the run's scope.

The Python 3.12 dependency set is pinned in `requirements-lock.txt`. `pyproject.toml` defines broader compatible dependencies for development; installing only those ranges can produce different results. A fixed seed alone does not guarantee identical results across library versions or numerical platforms.

| Setting | Default |
|---|---|
| Direction target | Positive next-observation close-to-close return |
| Initial training sample | 504 usable rows |
| Evaluation blocks | 63 rows, expanding training window, no overlapping test blocks |
| Models | Training-frequency and most-frequent baselines, logistic regression, linear SVM, histogram gradient boosting, random forest |
| Random forest | 300 trees, maximum depth 5, minimum leaf size 20, seed 42 |
| Trading rule | Long at probability ≥ 0.53; otherwise flat |
| Main execution assumption | Signal from the preceding row applied at the current close |
| Timing comparator | Same-close execution, explicitly labelled a diagnostic |
| Transaction costs | 5 basis points per unit of position turnover |
| Prediction uncertainty | Paired moving-block bootstrap of Brier-loss improvement over the training-frequency baseline; blocks of 10 and 20 rows, 1,000 draws, seed 42 |

These are script defaults, not a claim of optimal settings. `reports/run_manifest.json` records the configuration used alongside Python/dependency versions, data hashes, and source-version information.

## Read the outputs in order

1. **Check provenance and configuration.** Read `data/manifest.json` and `reports/run_manifest.json`. A hash identifies bytes, not the provider, licence, or economic meaning of a series.
2. **Inspect stored predictions.** `reports/predictions.csv` contains model-labelled predictions on shared evaluation dates. `model_comparison.csv` is computed from these predictions. The trading report uses the same random-forest predictions; the forest is fixed as the trading example rather than selected by the model-table ranking. Prediction dates label when forecasts are formed; backtest dates label the start of the earned return interval.
3. **Compare probability quality.** `prediction_uncertainty.csv` compares the forest with the training-frequency baseline using paired observations. This baseline predicts the positive-label fraction observed in each training fold; the separate majority baseline uses a hard class probability. Positive Brier-loss improvement favours the forest. An interval spanning zero does not establish improvement; an interval excluding zero still does not resolve sample reuse or generalization to another period.
4. **Inspect execution sensitivity.** `execution_comparison.csv` compares delayed-close execution with the same-close diagnostic on the same rows. `signal_backtest.csv` separates `signal_position` from executed `position`; the first delayed position is flat.
5. **Read performance and diagnostics.** Inspect returns, turnover, exposure, and drawdown alongside `calibration_table.csv` and the generated summary. Feature importance is descriptive, and the largest AUC in the model table is not an independently selected winner.

## Interpretation

The paired moving-block bootstrap resamples contiguous loss-difference blocks to retain some local dependence. The 95% percentile intervals are sensitivity intervals conditional on these fitted forecasts. Class-weighted forest and logistic outputs are uncalibrated probability scores. The models are not refitted in each draw; the procedure does not account for selecting among models or research variants. Two block lengths provide a limited sensitivity check, not a complete dependence model.

The classifier targets the next close-to-close move. Delaying a signal by one close changes the return interval to which that signal is applied; it does not retrain the model for a longer horizon or establish probability calibration for that later interval. This comparison measures sensitivity to the trading clock. Even delayed-close execution assumes an idealized fill.

For a stronger future study, fix the data sources and research protocol before collecting or reserving a new evaluation period. Keep development decisions out of that evaluation and report negative as well as positive outcomes. See the [roadmap](research_roadmap.md).
